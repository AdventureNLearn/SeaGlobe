# SeaGlobe build spec (v2)

What the app does and how it is put together. Paths are relative to the repository root.

## 1. Runtime

- Static web app in `web/`: `index.html`, `app.css`, `js/*.js`, `data/**`, `vendor/`, `textures/`, `fonts/`, `assets/`.
- Classic scripts only (no modules, no build step), so it runs from a local server, from `file://` (lite) and on a static host.
- Libraries: globe.gl 2.46.2; three.js r187 as `window.SEAGLOBE_THREE`; example add-ons (bloom, output pass, lensflare) as `window.SEAGLOBE_THREE_ADDONS`.
- Works with no network. Since v3.0 the only runtime requests to other hosts are optional and fail quietly: the
  read-only version check, the opt-in TIGERweb layer, the radio's YouTube player (on click), the xAI API (only with the
  visitor's own key), an R2 asset base (bundled fallbacks) and the PC-only BYO feeds; `data/csp.json` lists the hosts.
  "Go deeper" links are plain `target="_blank"` links. Details: `DESIGN-V3.md`, `GROK-ME-BUILD.md`.
- `serve.py` (standard library) serves `web/` on 127.0.0.1; `Start-SeaGlobe.cmd` runs it with `--open`.

## 2. Modules

| File | Role |
|---|---|
| `js/timemodel.js` | Astronomical years (−499 = 500 BCE), date parsing/labels, era lookup |
| `js/voyages.js` | Great-circle densify, schedules (dated / years / traffic), instance state, trails, active-vehicle cap |
| `js/vehicles.js` | 26 procedural vehicle models, one per `schema.vehicles` id, no placeholder fallback in use (detailed pass: smooth lofted hulls with waterline paint and wales, code-generated plank/sailcloth/steel textures, billowed sails, auto standing rigging, deck fittings, smoke), cached templates |
| `js/planet.js` | Earth shader (day/night/ocean shine/terminator/rim), stars, moon, satellites, sun + lensflare |
| `js/app.js` | Scene, modes, focus, routes, vehicles, wakes, labels, camera, picking, panels, Ship's Log, scripting API |
| `data/schema.js` | Timeline, eras, route types, vehicle list, record fields |
| `data/routes/*.json, *.js` | One file per route family (generated by `tools/build_routes.py`) |
| `data/deeper.js` | Go-deeper links and per-route mapping |

## 3. Modes

- **Sampler (idle)** — default when no date is given. A curated, rotating sample of 16 vessels (10 in lite) from mixed eras,
  types and regions (trireme, Roman merchantman, galley, longship, cog, dhow, junk, galleon, East Indiaman, frigate,
  caravans, steamship, steam train, container ship, jet…). Each vessel runs its own voyage at its own date; one is swapped
  out every 3.5 s with a fade (scale, halo and wake). Only the sample's routes are drawn, at low opacity. Slow auto-rotation,
  paused for 10 s after the user touches the globe. The Middle Passage is not used as decoration.
- **Timeline** — entered by play, the scrubber, an era button or a Ship's Log entry. All voyages active at the current date
  move (cap 56, lite 28; real-dated first).
- **Focus** — any of era, route type, goods, region, evidence, search text or a single Ship's Log entry. Matching routes and
  vessels are shown clearly; everything else drops to about 10% (routes at 6% alpha, vessels in a translucent ghost
  material, no wakes or labels). A "Focus" chip in the top bar shows the filter; × or Esc clears it. "Sampler" returns to idle.

## 4. Look

- Routes are coloured by **family** (legend panel, top left, lists the families in view); the Atlantic family keeps its muted colours.
- **Level of detail:** vessel labels are limited by zoom — about 5 when zoomed out (altitude > 2.2), 10 in the middle,
  22 close in — with named, real-dated voyages first and overlapping labels dropped. No labels in the chase camera.
- Vehicles point along their heading, sea vessels roll gently, fading wakes; air routes are arcs.
- Models: length normalised to 1, +Z forward, keel at y=0 then sunk per type (SINK table). Sailing types get shrouds,
  fore/back stays and mast-to-mast stays as thin lines. Textures are drawn on a canvas at run time (no image files);
  in Node tests the builders skip textures and still build geometry.
- **Surface placement:** globe.gl draws the Earth as a 4° faceted sphere (`SphereGeometry(100, 90, 45)`) whose flat
  triangles lie up to 0.12 % of R inside the ideal sphere. Vehicles and wakes are placed on that drawn surface
  (`SeaVehicles.facetScale`, `surfCoords` in app.js), so hulls sit in the water at their waterline and wheels and feet on
  the ground at any zoom. Route lines ride a constant 0.08 % of R above the drawn surface (visible, no depth fighting).
- **Space:** the first 10 decorative satellites are drawn as detailed models, the rest as points.

## 5. Ship's Log

- Glass panel (button "Ship's Log", key **L**, or **/** to search). Lists every route/voyage record.
- Search box (name, id, goods, family, vehicle, citations; all words must match).
- Filters: era, route type, goods category, region, evidence (dataset-derived / real dates / reconstruction); sort by date ↑, date ↓ or name.
  Filters drive **focus mode** on the globe.
- Each entry: name, years, type, vehicle, goods (or [UNKNOWN]), evidence/reconstruction flag, confidence, region, sources.
- Click or **Enter** on an entry: switch to the timeline, pick one of that route's voyages at departure, set the date, fly the
  camera there, play at 1×, select it and open its Voyage info.
- Keyboard: ↑/↓, Home/End, PageUp/PageDown, Enter/Space, Esc closes; ↑ from the first entry returns to search; listbox with `aria-activedescendant`.
- **Export CSV**: the filtered list (id, name, family, type, era, region, dates, vehicle, goods, evidence, reconstruction,
  confidence, timing, citations), UTF-8 with BOM, generated in the browser as a local download. Nothing is sent anywhere.
- Regions are coarse labels computed from each route's geometry by `tools/build_routes.py` (for filtering, not a historical claim).

## 6. Data records

Fields: `id, type, era, name, start_date, end_date, goods, goods_source, source, citation, citations, confidence,
confidence_level, reconstruction, family, region, vehicle, path, schedule, derived_from`, optional `notes, citation_check`.
Schedules: `dated` (real dates, optional dated anchors), `years` (published years; months/pace reconstructed),
`traffic` (illustrative, spaced to keep about `active` vessels on the route).

## 7. Tests

- `node --test tests/test_engine.mjs` — time model, eras, schema for every record, pre-1500 = reconstruction, no restricted
  derivation, dated anchors, cap, densify, go-deeper links, every vehicle builds, every type has its own model (no
  placeholder), hull waterline / ground contact per type, facet radius vs a raycast.
- `python -m unittest discover tests` — json/js copies match, index lists families, citations/flags, SOURCES.md coverage,
  no home paths/emails/secrets, no remote src/href/fetch in runtime code, file sizes < 50 MB.
- `node tests/test_app.mjs` — headless Chrome: eras have moving vessels without errors or external requests, era chip,
  click + follow, idle sampler variety and rotation, Ship's Log filter/search/keyboard/CSV, lite mode, `file://`.
  Also: surface model vs the drawn globe mesh, followed ship's hull crosses the waterline, train wheels on the ground.
- `node tools/vehicle_sheet.mjs` — close-up contact sheet of every model on its water / ground / air plane
  (screens/v2.1-all-vehicles.png); exits 1 on a missing model, a placeholder or a blank render.
- `node tools/closeup_check.mjs` — in-app follow-camera stills of sea, canal, rail, land and air vehicles (screens/v2.1-closeups.png).
